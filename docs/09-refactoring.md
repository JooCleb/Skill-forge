# Refatoração

Comece por um problema observável, como gatilhos ambíguos, instrução contraditória ou referência desatualizada. Preserve o objetivo e o contrato quando a mudança for apenas estrutural. Se o comportamento ou a saída mudar, registre isso explicitamente e avalie compatibilidade com usos anteriores.

No `workshop/refactor/`, use a [proposta](../templates/refactor-proposal.md) para ligar problema, trechos, alternativa, riscos e casos de comparação. Guarde versões pelo histórico Git ou registre artefatos antes/depois quando forem úteis. Após a mudança, execute os testes afetados e atualize catálogo e documentação se necessário.
